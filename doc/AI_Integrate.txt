==================================================================================================
                  TÀI LIỆU TỔNG HỢP KIẾN TRÚC VÀ LUỒNG XỬ LÝ HỆ THỐNG AI & AFFILIATE FOOD APP
===================================================================================================

Tài liệu này tóm tắt toàn bộ giải pháp kỹ thuật, cấu trúc cơ sở dữ liệu, luồng xử lý thời gian thực
và cơ chế tự động hóa sử dụng .NET Core Clean Architecture, AI (Gemini/OpenAI), Spoonacular API 
và Accesstrade API.

---------------------------------------------------------------------------------------------------
PHẦN 1: LUỒNG XỬ LÝ CHÍNH (REAL-TIME PIPELINE - 5 BƯỚC)
---------------------------------------------------------------------------------------------------
Luồng diễn ra trong vòng 5-10 giây kể từ khi người dùng thực hiện thao tác tìm kiếm món ăn:

Bước 1: Người dùng gửi yêu cầu (Client -> Backend)
    - Người dùng chọn các tiêu chí: Thiết bị nấu (Lò nướng), Chế độ ăn (Vegan), Ngân sách (< 100k).
    - Hệ thống tiếp nhận và kiểm tra phân quyền (Nếu chọn chế độ ăn đặc biệt như Keto/Vegan, 
      hệ thống kiểm tra trạng thái Premium trong bảng UserSubscription).

Bước 2: Lấy công thức thô (Backend -> Spoonacular API)
    - Backend gửi tham số sang Spoonacular API (`/recipes/complexSearch?diet=vegan&equipment=oven`).
    - Spoonacular trả về danh sách món ăn kèm mảng nguyên liệu thô bằng tiếng Anh.
    - Ví dụ: `["2 cups of all-purpose flour", "1 tbsp olive oil", "a pinch of salt"]`.

Bước 3: Phiên dịch và Khớp thực thể (Backend -> AI API)
    - Hệ thống kiểm tra bảng `IngredientDictionary` trước để xem từ khóa thô tiếng Anh đã có sẵn
      ID tiếng Việt chưa (Cơ chế Cache tối ưu chi phí).
    - Nếu chưa có, Backend gom các từ khóa chưa biết, kết hợp với danh sách Nguyên liệu chuẩn 
      (`StandardIngredient`) lấy từ DB tạo thành Prompt gửi sang AI (Gemini/OpenAI).
    - AI thực hiện xử lý ngôn ngữ tự nhiên, khớp các từ tiếng Anh sang ID nguyên liệu chuẩn 
      của hệ thống và trả về mảng JSON chứa các ID gọn gàng (Ví dụ: `[1, 2, 3]`).

Bước 4: Tính toán ngân sách & Gắn link kiếm tiền (Backend -> SQL Database)
    - Backend cầm danh sách các ID nguyên liệu chuẩn, chọc vào bảng `AffiliateProduct` để lấy 
      các link Shopee/TikTok Shop đang hoạt động (`IsActive == true`) kèm giá tiền thực tế.
    - Hệ thống cộng tổng tiền các nguyên liệu. Nếu vượt quá ngân sách 100.000đ của người dùng, 
      món ăn sẽ bị loại bỏ hoặc ưu tiên nhặt các link sản phẩm thuộc phân khúc giá rẻ hơn.

Bước 5: Trả kết quả (Backend -> Client)
    - Đóng gói dữ liệu thành JSON hoàn chỉnh gửi về Frontend hiển thị: Tên món, ảnh (Spoonacular), 
      các bước làm, tổng chi phí nguyên liệu và nút bấm "Mua nguyên liệu trên Shopee" 
      (chứa link Affiliate của bạn để nhận hoa hồng).

---------------------------------------------------------------------------------------------------
PHẦN 2: THIẾT KẾ CƠ SỞ DỮ LIỆU CỐT LÕI (DATABASE SCHEMA)
---------------------------------------------------------------------------------------------------
Hệ thống sử dụng kiến trúc lưu trữ tối giản (không lưu công thức nấu ăn, chỉ lưu dữ liệu thương mại):

1. Bảng `StandardIngredient` (Kho nguyên liệu chuẩn):
    - Lưu danh sách nguyên liệu gốc bằng tiếng Việt (Ví dụ: Ức gà, Muối tinh, Dầu oliu...).
    - Các trường chính: `Id (Guid)`, `Name (NVarChar)`, `Category (NVarChar)`.

2. Bảng `AffiliateProduct` (Kho sản phẩm kiếm tiền):
    - Lưu link tiếp thị liên kết thật và giá tiền từ các sàn thương mại điện tử.
    - Các trường chính: `Id`, `StandardIngredientId`, `ProductName`, `ProductUrl`, `CurrentPrice`, 
      `Platform (Shopee/Lazada)`, `IsActive (Bool)`, `LastUpdatedPriceAt`.

3. Bảng `SubscriptionPlan` (Quản lý gói cước Premium):
    - Lưu thông tin các gói dịch vụ thu phí (Ví dụ: Gói Free, Gói Tháng 49k, Gói Năm 399k).
    - Các trường chính: `Id`, `PlanName`, `Price (Value Object Money)`, `DurationInDays`, `FeaturesJson`.

4. Bảng `IngredientDictionary` (Từ điển bộ đệm AI Cache):
    - Lưu vết các từ khóa tiếng Anh thô đã từng được dịch để tái sử dụng, không cần gọi AI lại.
    - Các trường chính: `RawEnglishText (Key)`, `StandardIngredientId`.

---------------------------------------------------------------------------------------------------
PHẦN 3: BỘ CHẠY NGẦM TỰ ĐỘNG HÓA (AUTO-SEARCH AFFILIATE WORKER)
---------------------------------------------------------------------------------------------------
Để giải quyết bài toán "Khởi động lạnh" (chưa có link affiliate nào) và cập nhật giá tự động, 
hệ thống triển khai một `.NET BackgroundService` chạy ngầm (ví dụ: lúc 2h sáng):

Luồng hoạt động của Worker:
    - Bước 1: Quét bảng `StandardIngredient` theo từng mẻ (`BatchSize = 20`) để tìm các nguyên liệu 
      chưa đủ số lượng link Active hoặc dữ liệu giá đã cũ quá 24h.
    - Bước 2: Dùng tên tiếng Việt của nguyên liệu gọi sang API Datafeed thật của Accesstrade 
      (Ví dụ: `GET /v1/datafeeds?keyword=Dầu+oliu&merchant=shopee&limit=5`).
    - Bước 3: Áp dụng thư viện Polly (Retry Policy) để tự động thử lại 3 lần nếu API đối tác bị lỗi 
      mạng hoặc lỗi 429 (Quá tải lượt gọi).
    - Bước 4: Nhận kết quả JSON, chọn ra sản phẩm tối ưu nhất (Giá > 0, có sẵn link rút gọn).
    - Bước 5 (Quản lý vòng đời - Soft Delete): 
        + Thực hiện `Insert` bản ghi sản phẩm mới vào bảng `AffiliateProduct` với `IsActive = true`.
        + Kiểm tra nếu số lượng link hoạt động của nguyên liệu đó vượt quá giới hạn (Ví dụ: > 3 link), 
          hệ thống tự động chuyển trạng thái của các link cũ nhất thành `IsActive = false`. 
          Điều này giúp giữ lại tối đa 3 phân khúc giá mới nhất, loại bỏ link rác mà không làm mất 
          lịch sử dữ liệu.

---------------------------------------------------------------------------------------------------
PHẦN 4: HƯỚNG DẪN TÍCH HỢP AI ĐỂ LÀM ENTITY MATCHING
---------------------------------------------------------------------------------------------------
Khi viết code tích hợp AI (Gemini hoặc OpenAI API) ở tầng Infrastructure:

1. Kỹ thuật Prompt (Ép kiểu JSON):
    - Cần ra lệnh cho AI hoạt động như một hàm thuần túy (Pure Function). Truyền vào mảng tiếng Anh 
      từ Spoonacular và danh sách `Id + Name` tiếng Việt từ Database.
    - Ép sản phẩm đầu ra ở chế độ JSON Mode chỉ chứa duy nhất một mảng ID tương ứng.

2. Mô hình triển khai Code:
    - Tạo `IAiMatchingService` tại tầng Application.
    - Viết triển khai (Implementation) tại tầng Infrastructure bằng `HttpClient` hoặc SDK chính thức.
    - Đăng ký DI và bọc ngoài bằng bộ lọc dữ liệu (Cache Filter) để kiểm tra bảng `IngredientDictionary` 
      trước khi thực hiện lệnh gọi API tốn phí ra bên ngoài.
