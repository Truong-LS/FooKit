1. System Overview API (Dashboard Overview)

This API acts like a speedometer dashboard, providing a quick snapshot of the application's “health” and growth status immediately after the Admin logs in.

Endpoint: GET /api/v1/admin/dashboard/overview

Authentication: Required (JWT Token with Admin role required).

Request Parameters

No complex query parameters are required. Optionally, you can pass timezone_offset if you want “Today” calculations to match the Admin’s timezone instead of UTC time.

Response Structure (Response JSON)
{
  "timestamp": "2026-05-27T09:46:00Z",
  "users_metrics": {
    "total_users": 1500,
    "premium_users": 120,
    "new_users_today": 15
  },
  "content_metrics": {
    "meals_generated_today": 450,
    "total_active_affiliate_links": 2500
  },
  "system_health": {
    "is_worker_running": true,
    "last_affiliate_sync": "2026-05-27T02:00:00Z"
  }
}
Backend Processing Flow (Service Logic)

Use Entity Framework Core to query the related tables directly:

total_users: CountAsync() on the entire Users table.
premium_users: CountAsync() on the Users table with the condition that the current Subscription package has EndDate > DateTime.UtcNow.
meals_generated_today: CountAsync() on the meal generation history table (e.g., UserMealHistory) where CreatedAt falls within today’s date.
total_active_affiliate_links: CountAsync() on the AffiliateProduct table where IsActive == true.
2. Third-Party API Usage & Cost API

This is the API that helps you “protect your money.” To support this API, you should instruct the AI Agent to create an additional logging table in the database (e.g., ThirdPartyApiLog) so that every time the system calls Spoonacular or an AI provider, a new log entry is inserted to record token usage.

Endpoint: GET /api/v1/admin/dashboard/api-usage

Authentication: Required (JWT Token with Admin role required).

Request Parameters (Query Parameters)

Allow Admins to filter by a time range to review costs for a specific week or month.

start_date (example: 2026-05-01)
end_date (example: 2026-05-31)
Response Structure (Response JSON)
{
  "period": {
    "start": "2026-05-01",
    "end": "2026-05-31"
  },
  "total_estimated_cost_usd": 15.45,
  "details": {
    "ai_provider": {
      "name": "Google Gemini",
      "total_requests": 3200,
      "total_tokens_used": 1500000,
      "estimated_cost_usd": 3.75
    },
    "recipe_provider": {
      "name": "Spoonacular",
      "total_requests": 2500,
      "quota_used_percentage": 85.0,
      "estimated_cost_usd": 11.70
    }
  },
  "cache_efficiency": {
    "ai_cache_hit_rate_percentage": 78.5
  }
}
Backend Processing Flow (Service Logic)
Data Filtering

Query the ThirdPartyApiLog table within the start_date and end_date range.

AI Cost Calculation

Group (GroupBy) records by AI service provider and calculate the total TokensUsed. Then multiply by the current pricing of Google/OpenAI (for example: $2.50 per 1 million tokens) to calculate estimated_cost_usd.

Spoonacular Cost Calculation

Group records by the Spoonacular service and count the total number of requests. Calculate the used quota percentage based on your purchased subscription plan limits.

Optimization Metric (Cache Hit Rate)

This is the most important metric. It is calculated using the formula:

Number of ingredient retrievals from the database / Total number of ingredient translation requests

If this ratio is above 70%, it means your IngredientDictionary cache table is performing extremely efficiently, saving up to 70% of AI API costs.

If the ratio is low, you should review and optimize your caching algorithm.
